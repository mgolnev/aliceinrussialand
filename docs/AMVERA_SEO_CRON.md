# Очередь AI SEO

Очередь в PostgreSQL устойчива к перезапуску, таймауту модели и временному сбою сети.
Ручные поля не перезаписываются; задачи с `REVIEW`/`FAILED` не повторяются бесконечно.

## Amvera: постоянный серверный обработчик

Docker задаёт `AI_SEO_WORKER_ENABLED=true` только в runtime-слое. После запуска Next.js
`src/instrumentation.ts` включает один последовательный цикл на Node-процесс:

- первая проверка через 5 секунд, пустой очереди — раз в 30 секунд;
- после задачи следующая берётся через 250 мс, пока доступные задачи не закончатся;
- отложенные повторные попытки соблюдают `runAfter`, а зависшие задачи восстанавливаются
  существующим механизмом блокировок через 10 минут;
- после HTTP-таймаута цикл ждёт 10 минут: закрытие соединения не гарантирует остановку AI;
- перезапуск контейнера автоматически возобновляет обработку сохранённой очереди.

Нужен существующий `CRON_SECRET` в переменных Amvera. Новых секретов и сервисов не нужно.
Обработчик вызывает `POST http://127.0.0.1:PORT/api/cron/seo` с Bearer-секретом, без CDN.
Отдельный короткий запрос для каждой задачи сохраняет Next request context для обновления
кеша и не держит один HTTP-запрос на всю пачку. Внешний `GET` остаётся совместим с cron.

В админке кнопка **«Обработать всю очередь»** немедленно будит тот же цикл. Повторные
нажатия не запускают второй цикл, не ставят задачи заново и не сбрасывают ошибки/попытки.
Вкладку можно закрыть. Кнопка работает только с уже накопленной очередью; для отсутствующих
SEO/alt без задач есть «Подготовить автоматически». Статус показывает проверку worker,
число ожидающих/выполняемых задач и отдельно задачи, требующие внимания.

Очередь и атомарный захват задач хранятся в БД; таймер и диагностические отметки — только
в памяти текущего инстанса и сбрасываются после рестарта. При нескольких контейнерах
каждый имеет собственный цикл; атомарный захват не даёт взять одну задачу дважды,
но разные задачи могут выполняться параллельно. Основной режим Amvera — один контейнер.
Существующие адресные `after` для публикаций и резервный cron также сохраняют DB-защиту.

На Vercel цикл запрещён даже при `AI_SEO_WORKER_ENABLED=true`: там остаются `after`,
внешний cron и ручная обработка одной задачи. Локально флаг по умолчанию не задан;
не включайте его при подключении dev-сервера к производственной БД.

## Проверка после деплоя

1. В панели SEO должен появиться статус автообработки и время успешной проверки.
2. Существующие `PENDING` задачи должны уменьшаться без нажатий.
3. Кнопка всей очереди возвращает HTTP 202 быстро; следующие задачи идут последовательно.
4. При сетевой ошибке показывается предупреждение, а в логе — `[ai-seo-worker]` без секретов.
5. При пустой очереди обработчик не вызывает модель: только проверяет БД раз в 30 секунд.

## GitHub Actions — резервный планировщик

В `.github/workflows/seo-queue.yml` задано расписание каждые 5 минут, но GitHub может
задерживать или пропускать запуски. Поэтому это лишь резерв, не основной обработчик:
https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule

Workflow дважды вызывает защищённый endpoint очереди и не зависит от открытой вкладки.

В GitHub repository secrets нужно один раз добавить `CRON_SECRET` со значением
одноимённой переменной Amvera. Секрет не должен попадать в `.env.example`, Git
или логи workflow.

## Amvera Cron Job — альтернатива

Если GitHub Actions не используется, в панели Amvera можно создать отдельный
**Cron Job**, который вызывает:

```text
GET https://aliceinrussialand.ru/api/cron/seo
Authorization: Bearer <CRON_SECRET>
```

Расписание Amvera использует UTC и Quartz-синтаксис. Рекомендуемое расписание — раз в
10 минут:

```text
0 0/10 * * * ?
```

Укажите максимальное время работы 60 секунд и политику запуска `FORBID` (не начинать
второй запуск, пока предыдущий не завершён). `CRON_SECRET` должен совпадать с секретом
одноимённой переменной основного приложения; его не помещают в URL, код или Git.

Если серверный цикл включён в Amvera, внешний планировщик необязателен.
Отключение цикла: `AI_SEO_WORKER_ENABLED=false` и перезапуск контейнера.
